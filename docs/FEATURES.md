# Product capabilities

These descriptions summarize implemented product workflows, including isolated testing. They are not a claim that every workflow is approved for production or commercially available.

| Area | Product experience |
| --- | --- |
| Student workspace | Staff manage student profiles and review membership history within authorized studio scope. |
| Staff permissions | Server-enforced studio permissions separate staff administration from restricted check-in. |
| Student IDs | Stable QR credentials are separate from printable cards. An ID view remains available without an approved photo, using NO PHOTO. |
| ID presentation | Studio-owned templates, broad printed rank categories, badges, and authorized dimensions; default cards measure 2.5 × 3.5 inches. Exact progression remains separate. |
| Attendance | Reserved arrivals and walk-ins are distinct. Multiple sessions are supported; repeated confirmation for the same student and session does not create duplicate attendance. |
| Check-in privacy | Minimal student identity and a generic office alert; guardian, private, and fee details remain outside the restricted view. |
| Reviewed imports | Excel review preserves good data when updates are blank. ZIP photo matching uses scoped identifiers or explicit mappings and human review, with separate original, processed, and approved photos. |
| Obligations | Studio-owned fee settings and explicit assignments retain historical terms. Enabling a setting does not automatically create debt or collect payment. |
| Membership documents | Staff review originals and history; document upload and membership confirmation are separate actions. |

## Boundaries

Payment processing, automatic charges, facial recognition, and wallet passes are excluded. Parent/family portals, native mobile apps, and Meta/AI marketing remain deferred.
